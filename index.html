How it Works

For this project, I used chessboard.js to display the board, and chess.js to generate all the possible moves including castling, en passant, etc.


This program makes the best moves using an custom-made FEN evaluation algorithm. It parses the FEN string into an 8x8 grid using a for loop, and then runs it through all possible moves. I can get this list from calling "game.moves({ verbose: true });" and this generates a list of all moves. Since it takes a lot of time for it to generate the moves, I found it best practice to make a variable and get values from that instead. This helps keep the program running fast.

However, I ran into an error. since it only searches one depth deep it moved the knight out and kept moving the rook back and forth, and only captured when it needed to. This was bad, because it doesn't do any good moves, and it is easily beatable. One solution for this was to increase the depth of the bot. This just means how many moves in the bot looks for before finding the best move. So as of now, it looks at every move possible at a given position and from that position, it checks all possible moves from all the position, reaching a evaluation of 2 moves deep (or 2 plies deep)
